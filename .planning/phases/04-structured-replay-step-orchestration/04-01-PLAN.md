# Structured Replay Step Orchestration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `run_flow` from a run-level runner wrapper into a step-aware replay orchestrator that reports current/completed/remaining steps, per-step failure reasons, and step-scoped evidence.

**Architecture:** Keep `run_flow` as the replay-facing MCP tool, but move replay truth into MCP-native step orchestration. The implementation should normalize imported flow steps into a canonical replay-step model, execute each step through the existing action orchestration stack, persist step-level progress and evidence into session/audit surfaces, and preserve a runner-compatibility lane during migration.
The plan is not complete until step outcomes, replay progress, bounded stop/continue semantics, and step-scoped evidence are all represented in contracts, adapter runtime, tests, and user-facing docs.

**Tech Stack:** pnpm monorepo, TypeScript, `packages/contracts`, `packages/core`, `packages/adapter-maestro`, `packages/mcp-server`, existing `perform_action_with_evidence` orchestration, repo docs and tests.
