# Phase 06 Plan 03

## Goal

### Problem
The planning workspace now has a shared `mobile-e2e-readiness-baseline`, but Android-specific readiness still needs a dedicated refinement slice that translates the shared contract into concrete Android guidance across Compose, View-system, and hybrid app surfaces.

### Expected Outcome
- [ ] The planning workspace contains a concrete `android-e2e-readiness` draft that explicitly extends the baseline rather than redefining it.
- [ ] Android-specific readiness checks are grouped into clear overlays for Compose, Views, and hybrid screens.

### Non-goals
- Publishing a real Android skill file outside `.planning/`.
- Reworking the shared baseline vocabulary.
- Defining iOS-specific guidance in this slice.

## Plan

### Strategy
Refine Android-specific readiness as a downstream extension of the shared baseline. Keep the baseline contract intact, then add only Android-specific checks around selectors, semantics, deep links, synchronization, hybrid trees, and transition stability.

### Task Breakdown
1. Define the Android-specific extension boundaries that sit on top of the shared baseline.
2. Draft a dedicated Android skill spec artifact for Compose, Views, and hybrid surfaces.
3. Sync roadmap/state so the planning workspace shows Android refinement complete while keeping iOS as the next follow-on slice.
4. Record verification and handoff notes for future pressure testing and real skill publication.

### Risks / Unknowns
- Android guidance can easily drift into generic Android development advice if not kept anchored to E2E readiness.
- Compose-heavy examples may accidentally underweight View-system and hybrid apps.
- Future pressure testing may still split Compose into a separate real skill if checklist divergence becomes too large.
