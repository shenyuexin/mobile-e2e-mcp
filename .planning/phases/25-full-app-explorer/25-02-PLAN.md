# Phase 25 Plan 02

## Goal

### Problem
Explorer currently mixes shared traversal logic with platform-specific UI parsing and interaction semantics. New Android smoke fixes proved that shared changes can accidentally redefine the already-validated iOS path instead of merely extending Android support.

### Expected Outcome
- [ ] Commit `7804ac5d` is treated as the Explorer iOS behavior baseline and preserved through the refactor.
- [ ] Explorer gains an explicit platform hook layer, but shared abstractions are derived from validated iOS behavior first, not from current Android experimentation.
- [ ] Android XML parsing and row/actionability semantics can continue evolving behind provisional hooks without redefining iOS defaults.

### Non-goals
- No full fork of `packages/explorer` into two independent implementations.
- No MCP tool-surface expansion or contract changes outside explorer internals.
- No unrelated traversal/state-graph redesign beyond what is needed to introduce clear platform seams.
- No Android-driven shared abstraction changes until iOS parity gates pass against the `7804ac5d` baseline.

## Plan

### Strategy
Refactor explorer at the **platform semantics boundary**, not at the package boundary, and do it in an **iOS-baseline-first** sequence. First preserve the `7804ac5d` iOS behavior contract with explicit tests and hook extraction that is behavior-equivalent. Only after the iOS hook path is stable should Android continue integrating through a provisional hook implementation and feature-flag/shadow-mode style rollout.

### Task Breakdown
1. Define explorer platform hook boundaries and canonical shared snapshot/actionability contract.
2. Lock `7804ac5d` as the iOS behavioral baseline with fixture-backed parity tests (direct-tree + wrapped payload shapes, actionability, title extraction, back verification).
3. Extract iOS-specific parsing and semantics into the first hook implementation with no intended behavior change.
4. Rewire shared `snapshot`, `backtrack`, and `element-prioritizer` paths to consume hook outputs while keeping iOS behavior unchanged.
5. Introduce Android through an explicit provisional hook path, behind flags/checkpoints, without allowing Android experimentation to redefine shared defaults.
6. Sync architecture/planning docs so future explorer work follows the same iOS-baseline-first hook pattern as adapter-maestro-style platform seams.

### Risks / Unknowns
- iOS `inspect_ui` payload shape may vary between direct-tree and wrapped-result forms; hook interfaces must make that variability explicit and parity-tested.
- Some current explorer heuristics may secretly depend on raw Android/iOS field names; those dependencies must be surfaced before extraction.
- Over-normalizing platform semantics into one giant shared model could just recreate the current problem in a new file.
- Existing smoke behavior may rely on current label fallbacks that need preservation when moving to hook-derived metadata.
- Current Android behavior is still experimental; if used to shape shared contracts too early, it could silently regress the already-verified iOS lane.

### Done Criteria
- [ ] Explorer has a thin platform registry plus `android` / `ios` hook implementations.
- [ ] iOS hook path is verified to preserve `7804ac5d` behavior before Android hook cutover work becomes authoritative.
- [ ] Shared explorer core no longer parses raw XML/AX/JSON formats directly.
- [ ] `snapshot`, `backtrack`, and interactive-element classification consume normalized hook outputs.
- [ ] Android smoke remains green on the connected real device path, but Android remains explicitly provisional until follow-on hardening completes.
- [ ] iOS-focused regression fixtures cover direct-tree and wrapped payload shapes and gate merges touching shared explorer semantics.

## Implement

### Planned Changes
- `packages/explorer/src/explorer-platform.ts` — define hook interfaces, registry, baseline-preservation notes, and normalized explorer-facing platform contract.
- `packages/explorer/src/explorer-platform-ios.ts` — first hook implementation; preserve `7804ac5d` iOS parsing, title extraction, interactive semantics, selector token derivation, and back verification behavior.
- `packages/explorer/src/explorer-platform-android.ts` — provisional Android XML parsing, title extraction, actionable-row semantics, selector token derivation, and back verification helpers.
- `packages/explorer/src/ui-tree-parser.ts` — reduce to shared low-level helpers or move platform-specific entrypoints behind hooks.
- `packages/explorer/src/snapshot.ts` — consume hook-normalized snapshot/title/actionability output instead of raw platform parsing logic.
- `packages/explorer/src/backtrack.ts` — delegate platform-specific back evidence/verification logic to hooks.
- `packages/explorer/src/element-prioritizer.ts` — shift platform-specific actionability/type-table decisions into hook-provided metadata where appropriate.
- `packages/explorer/src/mcp-adapter.ts` — keep as thin bridge; remove accumulated platform policy where hooks now own semantics.
- `packages/explorer/tests/**/*.test.ts` — add Android/iOS regression coverage around parsing, actionability, and back semantics.
- `scripts/explorer/test-explorer.ts` / iOS validation fixtures as needed — preserve the known-good iOS execution path while hooks are extracted.
- `docs/architecture/explorer-hybrid-traversal-ascii.md` — document shared-core + platform-hooks boundary.
- `docs/engineering/explorer-stategraph-hybrid-redesign.md` — align future explorer redesign notes with the new hook boundary.

### Key Decisions To Preserve
- `7804ac5d` is the iOS Explorer behavior baseline for this refactor; preserving that lane takes priority over Android symmetry.
- Shared traversal/stategraph/reporting logic remains the canonical core; only platform semantics move behind hooks.
- The split point is **after MCP invocation but before explorer semantic interpretation**.
- Platform hooks should emit explorer-oriented normalized facts (`titleCandidates`, `isActionable`, `selectorTokens`, `backCapabilityEvidence`) instead of exposing raw platform payloads upstream.
- Do not reintroduce platform-specific field checks into shared core after the hook boundary is created.
- Prefer narrow, testable hook contracts over a large “universal UI node” abstraction with many optional fields.
- Android hooks are provisional during this phase: they may iterate, but they may not redefine shared defaults, parity expectations, or support-boundary language.

### Acceptance Criteria
- Explorer no longer needs shared code changes to understand both Android XML and iOS AX/JSON payload formats.
- A platform-specific parser/actionability fix can be localized to its hook module plus its own tests.
- iOS parity gates explicitly protect the validated `7804ac5d` lane before Android-driven shared changes may merge.
- Android real-device smoke remains reproducibly green after the refactor, but Android scope is still marked provisional/experimental until later hardening.
- iOS regression tests explicitly cover the payload-shape and clickable-container risks identified during the Android fix review.

### Success Criteria
- Future Android/iOS explorer fixes are naturally scoped to hook modules instead of shared parser/priority code.
- The explorer package aligns with the repo’s existing adapter-level platform-hook architecture instead of accumulating more hidden platform branches.
- Shared explorer core becomes smaller and easier to reason about, with platform responsibilities visible in code structure and tests.
- Android can keep iterating without being mistaken for the source of truth for shared Explorer abstractions.
