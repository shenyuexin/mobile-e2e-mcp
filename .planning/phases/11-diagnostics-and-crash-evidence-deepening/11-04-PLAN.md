# Phase 11 Plan 04

## Goal

### Problem
No bounded guardrails exist on remote file reads (`adb shell cat`, `adb pull`). Large trace files or unresponsive devices can hang operations for unbounded durations. Also, shell-interpolated paths are vulnerable to injection if filenames contain `"`, `$()`, or backticks.

### Expected Outcome
- [ ] New file `packages/adapter-maestro/src/diagnostics-pull.ts` exports `boundedRemoteFileRead`, `boundedRemoteFileReadBatch`, `checkRemoteFileSize`
- [ ] Primary read path is `adb shell "cat <escaped> | head -N"` (no root needed, natural size guard)
- [ ] `adb pull` is fallback when `cat` fails, with timeout + size guardrails
- [ ] `shellEscape` from `runtime-shared.ts` used for all shell-interpolated paths
- [ ] `executeRunner` used directly (no new `executeWithTimeout` wrapper — `executeRunner` already supports `timeoutMs`)
- [ ] Batch function propagates remaining budget to individual calls
- [ ] Temp files cleaned up in `finally` block for all error paths
- [ ] Unit tests cover all 6 status cases + 3 size check levels

### Non-goals
- Modifying existing `executeRunner` behavior
- Changing any MCP tool contracts
- Implementing ANR pull or iOS crash collection (that's 11-01, 11-02 — they depend on this)

## Plan

### Strategy
Build the bounded read utility first because Plans 11-01 and 11-02 depend on it. Keep it self-contained in a new file with injected dependencies for testability. Use `executeRunner` directly (which already returns `exitCode: null` on timeout) rather than creating a new wrapper.

### Task Breakdown
1. Create `packages/adapter-maestro/src/diagnostics-pull.ts` with `BoundedReadOptions` and `BoundedReadResult` interfaces
2. Implement `boundedRemoteFileRead` — primary path uses `adb shell "cat <shellEscape(path)> | head -N"`, fallback to `adb pull` with timeout
3. Implement `boundedAdbPullFallback` — uses dynamic remaining budget, 3-level size check, temp directory with try/finally cleanup
4. Implement `checkRemoteFileSize` — 3-level fallback: `stat -c %s` → `wc -c < file` → `cat file | wc -c`
5. Implement `boundedRemoteFileReadBatch` — iterates sequentially, computes `remainingBudget` per iteration, passes it to individual calls
6. All functions use `executeRunner` directly — check `exitCode === null` for timeout (NOT `result.completed`)
7. Add unit tests in `packages/adapter-maestro/test/diagnostics-pull.test.ts`:
   - `boundedRemoteFileRead`: success (shell_cat), success (adb_pull fallback), timeout, permission_denied, not_found, too_large, read_failed
   - `checkRemoteFileSize`: all 3 levels succeed, all 3 levels fail
   - `boundedRemoteFileReadBatch`: budget exhaustion, sequential execution

### Risks / Unknowns
- `stat -c %s` may not exist on Android < 8.0 — Level 3 (`cat | wc -c`) is O(n) and expected to timeout for large files, so it's best-effort only
- `shellEscape` uses single-quote escaping (`'value'` with inner `'` escaped as `'\''`) — this is correct for POSIX shell but needs verification on Android toybox shell
- Batch is sequential by design; parallel optimization deferred (O1)

### Key Decisions To Preserve
- `adb shell cat` with `head -N` is primary (not `adb pull`) — works on more device types
- `shellEscape` from `runtime-shared.ts` must be used for ALL shell-interpolated paths
- `executeRunner` is used directly — no `executeWithTimeout` wrapper
- `exitCode === null` means timeout (per executeRunner contract)
- Batch is sequential; remaining budget is computed and passed per iteration
- Temp directory cleanup in `finally` for ALL error paths (success, timeout, permission_denied, read_failed)
- Level 3 size check (`cat | wc -c`) is O(n), documented as best-effort, expected to timeout for large files
