# Phase 11 Plan 03

## Goal

### Problem
`buildLogSummary` does basic line counting and category bucketing but lacks structured crash attribution (process name, signal type, fault address, backtrace summary). AI agents must parse raw crash text themselves.

### Expected Outcome
- [ ] `crash-attribution.ts` is a new file (not in `action-outcome.ts`)
- [ ] `CrashAttribution` interface defined in `packages/contracts/src/types.ts`
- [ ] `buildCrashAttribution` has cheap pre-check guard (returns `undefined` when no crash signals)
- [ ] `detectCrashTypes` returns `CrashType[]` (supports hybrid: ANR + native_crash, etc.)
- [ ] `selectPrimaryCrashType` uses explicit priority ordering: anr > native_crash > watchdog > oom > uncaught_exception > unknown
- [ ] Crash type detection covers: anr, native_crash, uncaught_exception, oom, watchdog (Android + iOS)
- [ ] Suggested cause heuristics return at least 3 pattern matches with confidence
- [ ] `get_crash_signals` response includes `crashAttribution?: CrashAttribution` field (optional)
- [ ] `content` field remains human-readable string (backward compatible)
- [ ] Tests added with fixture crash reports
- [ ] Existing `buildLogSummary` unchanged

### Non-goals
- Modifying `buildLogSummary` (it stays as-is for generic log analysis)
- Full crash report symbolication
- ML-based crash analysis

## Plan

### Strategy
Create a new `crash-attribution.ts` file with `buildCrashAttribution`, `detectCrashTypes`, and `selectPrimaryCrashType` functions. Call `buildCrashAttribution` from `getCrashSignalsWithRuntime` only when content has crash-like signals (cheap pre-check). Add `CrashAttribution` interface to contracts. Keep `content` field human-readable (backward compatible).

### Task Breakdown
1. Create `packages/adapter-maestro/src/crash-attribution.ts`:
   - `detectCrashTypes(content, platform): CrashType[]` — detects all crash types in content
   - `selectPrimaryCrashType(types: CrashType[]): CrashType` — selects primary by priority ordering
   - `buildCrashAttribution(content, platform): CrashAttribution | undefined` — full attribution with cheap pre-check
   - `buildSuspectedCause(crashTypes, content, platform): { cause: string, confidence: string }` — heuristic matching
   - `buildSuggestedActions(crashAttribution): string[]` — actionable suggestions
2. Add `CrashAttribution` and `CrashType` interfaces in `packages/contracts/src/types.ts`
3. Add `crashAttribution?: CrashAttribution` to `GetCrashSignalsData` in contracts
4. Update `getCrashSignalsWithRuntime` in `device-runtime.ts` to call `buildCrashAttribution` when content has crash signals
5. Add tests with fixture crash reports (ANR, native crash, iOS crash, OOM, hybrid)
6. Verify `buildLogSummary` unchanged

### Risks / Unknowns
- Crash heuristic patterns may be incomplete for some crash types — start with 5 high-confidence patterns, expand based on real-world usage
- `buildSuspectedCause` heuristic table may produce false positives — confidence levels (high/medium/low) mitigate this
- Hybrid crash types (ANR + SIGKILL) — `CrashType[]` handles this, but `primaryCrashType` selection must be deterministic
