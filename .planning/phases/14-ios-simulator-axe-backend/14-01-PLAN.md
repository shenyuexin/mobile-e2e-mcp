# Phase 14 Plan 01

## Objective

- **What:** Introduce [AXe CLI](https://github.com/cameroncooke/AXe) as the primary iOS simulator backend for hierarchy capture, tap, type, swipe — replacing the Phase 13 simctl approach where simctl lacks accessibility capabilities, and completing idb deprecation.
- **Why:** Phase 13 discovered that `xcrun simctl` has NO `accessibility dump` command. simctl can do tap/type/swipe/screenshot but NOT hierarchy capture. AXe is a single-binary CLI tool that provides all 5 capabilities (describe-ui, tap, type, swipe, screenshot) using Apple's Accessibility APIs + idb's lower-level frameworks, without requiring a daemon process. This simplifies the codebase to one simulator backend instead of two partial ones.
- **User impact:** macOS users need `brew install axe` for full iOS simulator support. doctor warns if axe is missing.

## Context: Why Phase 13's simctl assumption was wrong

Phase 13 assumed `xcrun simctl spawn <udid> accessibility dump` existed. **It doesn't.** simctl's `io` subcommand only supports `screenshot`, `recordVideo`, `enumerate`, and `poll`. The `accessibility dump` subcommand does not exist in any version of simctl.

This means Phase 13's `SimctlSimulatorBackend.buildHierarchyCaptureCommand()` returns `["xcrun", "simctl", "spawn", deviceId, "accessibility", "dump"]` which always fails with `NSPOSIXErrorDomain code=2: No such file or directory`.

## AXe CLI Discovery

[AXe](https://github.com/cameroncooke/AXe) is a single-binary CLI tool (v1.6.0, installed via `brew install cameroncooke/axe/axe`) that provides all 5 simulator UI capabilities:

```bash
axe describe-ui --udid <UDID>          # Hierarchy capture (JSON output)
axe tap -x X -y Y --udid <UDID>        # Coordinate tap
axe type "text" --udid <UDID>          # Text input
axe swipe --start-x X1 --start-y Y1 --end-x X2 --end-y Y2 --udid <UDID>
axe screenshot --udid <UDID> --output <path>
```

Key advantages over idb:
- **Single binary**, no daemon process (no `idb_companion`)
- Uses Apple's Accessibility APIs + idb's lower-level frameworks directly
- Actively maintained (2026)
- Additional capabilities: hardware buttons, HID keyboard, video streaming, batch commands

## AXe JSON Output Format — VALIDATED

**Research completed 2026-04-07 on booted simulator (iPhone 16 Plus, iOS 18.5).**

axe `describe-ui` outputs a JSON array of nested accessibility nodes. **`parseIosInspectNodes()` parses axe output with ZERO modifications.**

Verified compatible fields:
| Field | axe key | parseIosInspectNodes reads | Compatible? |
|---|---|---|---|
| `type` | `type` | `node.type` | ✅ Exact match (`"Button"`, `"Application"`, etc.) |
| `identifier` | `AXUniqueId` | `node.identifier` / `node.AXIdentifier` / `node.id` | ✅ `AXUniqueId` works via fallback chain |
| `label` | `AXLabel` | `node.label` / `node.name` | ✅ `AXLabel` present |
| `frame` | `frame` | `node.frame {x, y, width, height}` | ✅ Exact match |
| `children` | `children` | `node.children` (recursive) | ✅ Exact match |
| `enabled` | `enabled` | `node.enabled` | ✅ Exact match |
| `clickable` | computed from type | `["Button", "Link", "Cell"].includes(type)` | ✅ axe `type` values match |
| `custom_actions` | `custom_actions` | `node.custom_actions` | ✅ Exact match |
| `className` | computed | `node.type` mapped | ✅ Same as idb |
| `text` | computed | `title` / `value` / `label` fallback | ✅ axe has all three |

Additional fields in axe (ignored by parser, safe):
- `role_description` — human-readable role ("button", "application")
- `AXValue` — accessibility value ("小组件", "4月07日 星期二")
- `role` — full AX role string ("AXButton")
- `pid` — process ID
- `AXFrame` — string format of frame ("{{x, y}, {w, h}}")
- `content_required`, `subrole`, `help`

## AXe vs idb vs simctl comparison

| Capability | idb | simctl | axe |
|---|---|---|---|
| hierarchy (describe-ui) | ✅ `idb ui describe-all` | ❌ N/A | ✅ `axe describe-ui` |
| tap | ✅ `idb ui tap` | ✅ `simctl io tap` | ✅ `axe tap` |
| type | ✅ `idb ui text` | ✅ `simctl keyboard type` | ✅ `axe type` |
| swipe | ✅ `idb ui swipe` | ✅ `simctl io swipe` | ✅ `axe swipe` |
| screenshot | ✅ | ✅ `simctl io screenshot` | ✅ `axe screenshot` |
| Requires daemon | ✅ idb_companion | ❌ No | ❌ No |
| Maintained | ❌ No (3+ years) | ✅ Yes (Apple) | ✅ Yes (active) |
| Install | `pipx + brew` | Built-in Xcode | `brew install axe` |
| Single binary | ❌ No | ✅ Yes | ✅ Yes |

**Decision:** Use axe for all simulator UI actions (hierarchy + tap + type + swipe). Keep simctl only for screenshot. This reduces backend count from 3 (idb + simctl + axe) to 2 (axe + simctl-screenshot-only), simplifying the codebase.

### Backend Selection Logic (Updated from Phase 13)

```
1. Environment variable
   IOS_EXECUTION_BACKEND=axe|simctl|devicectl|maestro|idb
   ├─ "axe" → axe backend (simulators)
   ├─ "simctl" → simctl backend (screenshot only — warn if used for UI actions)
   ├─ "devicectl" → devicectl backend (physical devices)
   ├─ "idb" → deprecation warning, still works (legacy compatibility)
   └─ invalid → ConfigurationError

2. Auto-detect (env var not set)
   if (isIosSimulatorId(deviceId)) → axe backend
   if (isIosPhysicalDeviceId(deviceId)) → devicectl backend

3. Availability check (axe not installed → fall back)
   For simulators:
     axe available? → use axe
     ↓ no
     idb available? → use idb (with warning)
     ↓ no
     throw ConfigurationError (no simulator hierarchy backend available)

   For physical devices:
     devicectl available? → use devicectl
     ↓ no
     maestro available? → use maestro
     ↓ no
     throw ConfigurationError
```

### Key Design Decisions

| Decision | Rationale |
|---|---|
| AXe replaces simctl for tap/type/swipe | Consolidates to one simulator backend; simctl's tap/type/swipe are untested; axe is purpose-built for this |
| Keep simctl for screenshot | simctl `io screenshot` is well-tested and reliable; no reason to change what works |
| AXe is opt-in (user installs via brew) | External dependency; doctor warns if missing; graceful fallback to idb if both missing |
| axe describe-ui JSON may need parser shim | AXe output format is similar but not identical to idb; need to validate with actual fixture |
| No new dependencies in package.json | AXe is installed system-wide via brew, not as an npm dependency |
