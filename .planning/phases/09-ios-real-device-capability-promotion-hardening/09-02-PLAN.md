# Phase 09 Plan 02

## Goal

### Problem
Current iOS physical-device actions (`tap`, `type_text`) still route through external Maestro CLI as the primary lane, while runner startup failures are hard to diagnose quickly in real-device scenarios.

### Expected Outcome
- [x] iOS physical-device `tap/type_text` use a self-owned local executor as primary lane.
- [x] Startup/handshake failures expose deterministic reason buckets (preflight, install, launch, channel, first-command) with linked artifacts.
- [x] Existing MCP tool contracts and fallback behavior remain stable for callers.

### Non-goals
- Full iOS backend rewrite across all tools in one slice.
- Replacing XCTest/Xcode signing requirements on physical devices.
- Feature expansion beyond tap/type_text (e.g. full replay semantics) in this plan.

## Plan

### Strategy
Introduce a backend seam for iOS physical-device action execution, implement a self-owned local XCUITest executor behind that seam, keep Maestro CLI as explicit fallback, and add deterministic startup diagnostics so `code74/dtxproxy` can be classified and triaged from first evidence pass.

### Task Breakdown
1. **Create iOS physical action backend seam (no behavior break):**
   - Add an internal `IosPhysicalActionBackend` abstraction in adapter runtime.
   - Keep current output envelope shape (`status`, `reasonCode`, `artifacts`, `nextSuggestions`) unchanged.
2. **Implement self-owned local executor path (tap/type only):**
   - Local executor uses cached `.xctestrun` + `xcodebuild test-without-building` startup contract.
   - Add bounded startup timeout and bounded retries only for retryable transient phases.
3. **Keep explicit fallback lane:**
   - On local-executor startup failure bucket, fallback to legacy Maestro CLI path only when fallback policy allows.
   - Record `fallbackUsed`, `fallbackReason`, and backend selection in artifacts/summary.
4. **Add deterministic startup diagnostics:**
   - Persist invocation manifest (device/Xcode/UDID/bundle IDs/command/env).
   - Persist xcodebuild stdout/stderr + xcresult pointers + phase markers.
   - Add reason-code mapping for preflight-lock/deviceprep, bundle mismatch, code74, dtxproxy channel refusal, first-command timeout.
5. **Server/tool descriptor and docs alignment:**
   - Update wording for iOS physical action lane to reflect self-owned primary path + explicit fallback.
   - Keep proof-gated wording where evidence is still partial.

### Risks / Unknowns
- iOS physical-device lock-state/deviceprep blocks can mask real handshake behavior.
- XCTest/Xcode dependency remains unavoidable on physical devices; migration removes external CLI dependency, not platform constraints.
- Cached xctestrun invalidation rules may drift if Xcode/device/OS matrix changes without explicit keying.

### Done Criteria
- [x] iOS physical `tap/type_text` first path is self-owned executor, not direct Maestro CLI.
- [x] Fallback is explicit and auditable in result envelopes/artifacts.
- [x] Failure classification includes deterministic startup phase + reason buckets.
- [x] Tests cover backend selection, fallback behavior, and reason-code mapping.
