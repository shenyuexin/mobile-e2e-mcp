# Phase 11 Plan 02

## Goal

### Problem
`executeCrashSignalsCapture` for iOS only works for simulators (reads `~/Library/Logs/CrashReporter` locally). Physical devices (`isIosPhysicalDeviceId(deviceId) === true`) have zero crash log collection path.

### Expected Outcome
- [ ] `collectIosPhysicalCrashLogs` is a private function in `device-runtime-ios.ts` (not on shared hooks)
- [ ] Tier 1 (`devicectl`) attempted first; explicit success/failure/no-data semantics
- [ ] Tier 2 (`idevicecrashreport`) attempted only if tier 1 returns `tool_not_available` or `device_disconnected`
- [ ] Tier 3 (`idevicesyslog`) uses time-bounded window (5 min), date resolved in Node.js via `new Date()`, NOT shell `$(date ...)`
- [ ] `missingToolingAdvice` tells user which tool to install if all tiers fail
- [ ] `appId` filtering works per tier
- [ ] iOS crash report parser extracts: process name, exception type, crashed thread frames
- [ ] Existing simulator path unchanged
- [ ] `platformExtensions` bag used for result extension (consistent with Plan 11-01)

### Non-goals
- Modifying shared `DeviceRuntimePlatformHooks` interface
- Changing simulator crash collection path
- Full crash report symbolication

## Plan

### Strategy
Add a private `collectIosPhysicalCrashLogs` function in `device-runtime-ios.ts` with 3-tier fallback: `devicectl` → `idevicecrashreport` → `idevicesyslog`. Branch `executeCrashSignalsCapture` on `isIosPhysicalDeviceId(deviceId)`. Use `platformExtensions` bag to carry structured data.

### Task Breakdown
1. Add private `collectIosPhysicalCrashLogs` function in `device-runtime-ios.ts`:
   - Accepts `repoRoot, deviceId, appId?`
   - Returns `IosPhysicalCrashResult`
2. Implement Tier 1: `xcrun devicectl device info crashes --device <udid>`
   - Parse JSON output for crash entries
   - Filter by `appId` if provided
   - Extract up to 3 most recent crashes
3. Implement Tier 2: `idevicecrashreport -k <local-dir> --udid <udid>`
   - Pull to temp dir, read `.crash` files
   - Parse crash report format (process name, exception type, crashed thread)
   - Filter by `appId` in file content
   - Clean up temp dir in `finally`
4. Implement Tier 3: `idevicesyslog` with time-bounded window
   - Date resolved in Node.js: `new Date(Date.now() - 5 * 60 * 1000)`
   - Format: `2026-04-05 10:25:00`
   - Filter by `appId` via grep if provided
5. Add `IosPhysicalCrashResult` interface in `device-runtime-ios.ts` (private to module)
6. Update `executeCrashSignalsCapture` to branch on `isIosPhysicalDeviceId(deviceId)`
7. Add iOS crash report parser (regex-based extraction)
8. Add tests: mock tier responses, verify fallback logic

### Risks / Unknowns
- `xcrun devicectl device info crashes` JSON format may differ from expected — research pending; fall back to tier 2 if incompatible
- `libimobiledevice` may not be installed — tier 2/3 unavailable; `missingToolingAdvice` guides user
- iOS crash report format varies by iOS version — parse defensively with optional fields
