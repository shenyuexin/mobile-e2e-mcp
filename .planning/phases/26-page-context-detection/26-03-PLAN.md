# Phase 26 Plan 03 — Remove WDA `/source` From The Pre-flight Path

## Goal

### Problem

The external page-context design still allows iOS real-device pre-flight to depend on WDA `/source`. In this repo, `/source` is the real-device hierarchy-capture path used for UI inspection/query/resolve/wait behavior, while lightweight availability probing is done via WDA `/status`. If Phase 26 uses `/source` as a default pre-flight gate, it turns a deterministic readiness check into a heavy hierarchy fetch and blurs the boundary between pre-flight health checks and runtime UI capture.

### Expected Outcome

- [ ] Phase 26 records one explicit rule that iOS real-device pre-flight must not depend on WDA `/source`.
- [ ] Phase 26 records the allowed lightweight pre-flight signals for real-device page-context detection.
- [ ] Future runtime slices can still use `/source` where full hierarchy capture is genuinely required, without leaking it back into the pre-flight path.

### Non-goals

- Removing WDA `/source` from the repo entirely.
- Replacing hierarchy capture for `inspect_ui`, `query_ui`, `resolve_ui_target`, or `wait_for_ui`.
- Designing the final iOS real-device detector internals beyond the pre-flight boundary.
- Implementing bounded fallback logic in this slice.

## Scope

### In Scope

- Define the pre-flight boundary for iOS real-device page-context detection.
- Distinguish lightweight WDA health/probe signals from full hierarchy capture.
- Define where `/source` remains allowed and where it becomes forbidden.
- Record the truth owners that must stay aligned when this boundary is implemented later.

### Out of Scope

- Reworking all existing WDA-backed hierarchy consumers.
- Refactoring simulator (`axe`) hierarchy polling.
- General performance tuning unrelated to the pre-flight boundary.

## Plan

### Strategy

Treat this slice as a deterministic-boundary gate. Start from live repo behavior: `ios-backend-wda.ts` uses `GET /status` for availability probing and `GET /source` for hierarchy capture; `ui-runtime.ts` uses `/source` for real-device iOS hierarchy reads; `doctor-runtime.ts` performs health/readiness checks separately from hierarchy capture; and the WDA setup guide documents `/status` as connectivity verification while warning that heavy hierarchy capture can destabilize WDA. Use that truth to define a Phase 26-safe rule: pre-flight may use lightweight deterministic signals, but `/source` is reserved for explicit hierarchy-reading flows, explicit refresh, diagnostics, or bounded fallback.

### Task Breakdown

1. Read the live WDA backend and record the current separation between `probeAvailability()` on `/status` and hierarchy capture on `/source`.
2. Read the current iOS runtime hierarchy path and record where `/source` is intentionally used today for UI-tree capture.
3. Define the Phase 26 pre-flight rule for real devices: what counts as allowed lightweight signal versus forbidden heavy hierarchy fetch.
4. Record the allowed post-boundary uses of `/source` — actual hierarchy-reading tools, explicit refresh, slow diagnostics, or bounded fallback if later slices justify it.
5. Record the acceptance rule that page-context pre-flight cannot quietly route through `/source`, even if downstream parsing remains shallow.

### Risks / Unknowns

- Because the repo already uses `/source` successfully for hierarchy capture, implementers may conflate “supported runtime path” with “acceptable pre-flight path.”
- Some page-context heuristics may feel easier to implement with full-tree reads; this slice must prevent convenience from redefining deterministic-first pre-flight behavior.
- If the boundary is written too loosely, later slices may reintroduce `/source` through an “implicit refresh” or “cheap probe” loophole.

### Done Criteria

- [ ] The package contains one explicit rule describing where `/source` remains allowed.
- [ ] Future slices no longer need to guess whether hierarchy capture is part of page-context pre-flight.

### Key Decisions To Preserve

- WDA `/source` remains a supported hierarchy-capture path for iOS physical-device UI inspection flows.
- WDA `/source` is **not** an acceptable default pre-flight path for page-context gating.
- Lightweight WDA health/readiness probes should stay separate from hierarchy capture.
- Shallow client-side parsing does not make `/source` a lightweight pre-flight signal, because the heavy server-side hierarchy serialization still happened.
- If later slices need full-tree data, they must justify that as explicit hierarchy capture or bounded fallback, not smuggle it into pre-flight.
