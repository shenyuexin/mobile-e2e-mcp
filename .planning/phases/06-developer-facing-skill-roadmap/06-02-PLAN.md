# Phase 06 Plan 02

## Goal

### Problem
Phase 06 currently contains concrete Android and iOS readiness skill drafts, but it lacks a thin cross-platform baseline that defines the shared terminology, minimum contracts, and output shape those platform-specific skills should inherit.

### Expected Outcome
- [ ] The planning workspace contains a concrete `mobile-e2e-readiness-baseline` draft that defines the shared E2E readiness contract across platforms.
- [ ] The sequencing between baseline, Android, and iOS follow-on skill slices is explicit and durable.

### Non-goals
- Publishing a real skill file outside `.planning/`.
- Collapsing Android or iOS-specific guidance into the baseline.
- Changing public support claims or product docs.

## Plan

### Strategy
Create a thin baseline skill spec that captures only the shared contract: deterministic entry, stable locators, ready/busy/blocked state, reset semantics, evidence hooks, and remediation framing. Keep platform implementation details out of the baseline, then reopen Phase 06 inventory so Android and iOS become explicit downstream refinement slices.

### Task Breakdown
1. Reopen Phase 06 with a new baseline-first execution order.
2. Draft a standalone baseline skill spec artifact under the Phase 06 folder.
3. Sync roadmap, state, and durable planning decisions so the approved sequence is preserved.
4. Record execution evidence and follow-on work for Android and iOS refinement slices.

### Risks / Unknowns
- The baseline could become too generic if it tries to absorb platform-specific implementation details.
- Future platform refinements may still reveal that some terminology needs to move back down into platform layers.
- Reopening a completed phase requires careful roadmap/state sync so future sessions do not misread the planning state.
