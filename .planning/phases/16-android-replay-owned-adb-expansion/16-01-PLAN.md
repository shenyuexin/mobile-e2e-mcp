# Phase 16 Plan 01

## Objective

- **What:** Expand the Android owned-adb replay backend to cover 9 currently-unsupported Maestro commands, eliminating the need for `dev.mobile.maestro` + `dev.mobile.maestro.test` helper apps in virtually all replay scenarios.
- **Why:** Phase 10 (commit `56170b7`) established the owned-adb primary lane but only covered 4 commands (launchApp, tapOn with selector, inputText, assertVisible). Any flow with coordinate taps, swipes, back, home, etc. still falls back to Maestro helper apps. All 9 remaining commands have direct `adb shell` equivalents — no helper app needed.
- **Output:** Extended `buildReplayPlanFromFlowYaml()` parser + owned-adb execution paths for all 9 commands.

## Current State

From `replay-step-planner.ts`, currently **supported** (owned-adb):
- `launchApp` → `adb shell monkey -p <package> -c android.intent.category.LAUNCHER 1`
- `tapOn` (with selector: text/id/identifier) → `adb shell uiautomator dump` + `adb shell input tap x y`
- `inputText` → `adb shell input text <text>`
- `assertVisible` → `adb shell uiautomator dump` + grep

Currently **unsupported** (triggers Maestro fallback):
| Maestro Command | ADB Equivalent | Notes |
|---|---|---|
| `tapOn` (with point coordinates) | `adb shell input tap <x> <y>` | Direct coordinate tap |
| `swipe` | `adb shell input swipe <x1> <y1> <x2> <y2> <duration>` | Includes duration in ms |
| `back` | `adb shell input keyevent 4` | KEYCODE_BACK |
| `home` | `adb shell input keyevent 3` | KEYCODE_HOME |
| `hideKeyboard` | `adb shell input keyevent 4` (or 111 for KEYCODE_ESCAPE) | Same as back |
| `stopApp` / `killApp` | `adb shell am force-stop <package>` | Need to resolve package from flow |
| `clearState` | `adb shell pm clear <package>` | Clears app data |
| `assertNotVisible` | `adb shell uiautomator dump` + grep absence | Inverse of assertVisible |
| `runFlow` | Recursive: load sub-flow and inline steps | Or skip with warning |

## Known Issues and Mitigations (Oracle Review Findings)

| # | Issue | Severity | Mitigation in Plan |
|---|---|---|---|
| 1 | `input text` doesn't support spaces — `adb shell input text "hello world"` splits on space | 🟡 Medium | Use `%s` for spaces: `adb shell input text "hello%sworld"`. Also escape special chars (`@` → `%40`, etc.) |
| 2 | `tapOn.point` is resolution-dependent — coordinates from 1080p device are wrong on 1440p | 🟡 Medium | Add resolution detection (`adb shell wm size`) and coordinate scaling. Store recording resolution, scale at replay time. Warning remains for edge cases. |
| 3 | `runFlow` sub-flow inlining can cause infinite loops with circular references | 🟡 Low | Detect circular references during plan building (track loaded flow paths, error on cycle) |
| 4 | `assertNotVisible` using grep on raw XML is fragile and can produce false positives | 🟡 Medium | Reuse existing `parseAndroidUiHierarchyNodes()` XML parser. After parsing, search for matching node. If found → assertion FAILS; if not found → assertion PASSES |

## Risk Mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Coordinate tap breaks on different screen resolutions | Medium | Medium | Resolution detection + scaling in Wave 2; warning in replay step metadata; fallback to selector-based tap when possible |
| assertNotVisible parsing is fragile (XML format varies by OEM) | Low | Medium | Reuse existing `parseAndroidUiHierarchyNodes()` which already handles OEM variations; not raw grep |
| runFlow sub-flow inlining causes infinite loop (circular references) | Low | Low | Detect circular references during plan building (track loaded flow paths in a Set, error on cycle) |
| input text with special characters fails silently | Medium | Low | Escape helper function handles spaces (`%s`), `@` (`%40`), `&` (`%26`), etc. Tested with representative inputs |
| Some OEMs remap keyevent codes (back/home) | Low | Low | Use standard keyevent codes (3=HOME, 4=BACK) which are universal across Android; document OEM-specific behavior if found |
