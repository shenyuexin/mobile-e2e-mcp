# Phase 30.1 Plan 01 Summary: Network Failure Policy Diagnosis

## What Changed

- Added `diagnose_network_failure` as a first-class MCP diagnostic capability.
- Added failure-first diagnosis contracts for request evidence, classification, release assessment, and confidence.
- Added adapter implementation in `packages/adapter-maestro/src/network-failure-diagnosis.ts`.
- Reused `inspectNetworkPolicyWithMaestro` as the lower-level Android cleartext / iOS ATS policy checker.
- Added MCP server handler, registry descriptor, contract map entry, tool-name constant, and capability-profile entries.
- Added docs explaining the boundary between `capture_js_network_events`, `probe_network_readiness`, `diagnose_network_failure`, and `inspect_network_policy`.
- Added a debug-evidence advisory so network-layer diagnosis points agents toward `diagnose_network_failure` when a failed request URL is available.

## Deviations From Plan

- The plan called for possible integration with `rank_failure_candidates` and `explain_last_failure`.
- Implementation kept integration advisory-only in debug evidence because automatic artifact reads from broader tools would add hidden IO and could surprise callers.
- This stays within scope because `diagnose_network_failure` is explicit, deterministic, and existing diagnosis surfaces now point agents toward it when network evidence is present.
