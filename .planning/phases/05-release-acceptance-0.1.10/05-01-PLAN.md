# Phase 05 Plan 01

## Goal

### Problem
The current candidate range `7db6eceb..abd01e05` changes shipped runtime behavior, but the repository does not yet have packaged-runtime evidence proving that npm release `0.1.10` is safe and semver-appropriate as a patch.

### Expected Outcome
- [ ] We have a concrete publish / defer / re-scope decision for `0.1.10` backed by packaged-runtime evidence.
- [ ] We know whether the npm-packed package works without repo-only files and whether the candidate change set fits patch-release risk.

### Non-goals
- Actually publishing to npm or pushing a release tag in this plan.
- Expanding replay behavior beyond the already landed Phase 04 preview scope.
- Reworking unrelated roadmap items outside the release-decision path.

## Plan

### Strategy
Validate the candidate exactly the way a downstream consumer would experience it: inspect the packaged artifact, run release-grade build/type/test checks, exercise the packaged runtime path, check public-doc sync expectations, then record whether the change set is acceptable for patch release semantics.

### Task Breakdown
1. Validate the release surface: inspect `@shenyuexin/mobile-e2e-mcp` package contents, bundle output, and any dependency on repo-only files.
2. Run release-grade regression checks for the candidate range, including build, typecheck, MCP-server tests, and the strongest relevant smoke path.
3. Exercise an npm-like packaged runtime path and confirm whether the shipped package can be used without hidden source-checkout assumptions.
4. Review semver fit, doc-sync obligations, and release automation expectations, then record a publish / defer / re-scope decision.

### Risks / Unknowns
- The packaged tarball may omit runtime-critical assets or assumptions that still work from a source checkout.
- The candidate may be functionally correct but too large or behaviorally meaningful for a patch semver signal.
- Public docs may lag behind capability-governed runtime changes in the candidate range.

### Done Criteria
- [ ] A `05-01-VERIFY.md` artifact records packaged-runtime evidence, regression results, and a release decision.
- [ ] The final decision clearly states whether `0.1.10` is acceptable as a patch release or must be deferred / re-scoped.

- The final recommendation explicitly states whether `0.1.10` is semver-appropriate as a patch release.
