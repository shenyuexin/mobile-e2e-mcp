# Capability Truth Language Audit Plan

> **For agentic workers:** keep this plan focused on wording, support boundaries, and evidence alignment. Do not drift into product implementation or new capability claims.

**Goal:** Audit and trim overclaimed support language across the repo's main capability surfaces so shipped truth and published truth match.

**Architecture:** This is a documentation truth pass. It should update the words that describe capability, not the runtime capability itself. The work should make it harder for README, architecture, and support docs to imply parity that the live registry does not actually prove.

**Tech Stack:** README docs, architecture docs, delivery docs, support-boundary guidance, and current support/evidence artifacts.
