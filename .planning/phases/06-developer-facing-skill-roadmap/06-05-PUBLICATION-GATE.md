# Phase 06 Plan 05 Publication Gate

## No real skill publication before these conditions pass

The readiness drafts must **not** be promoted into real skill files until all of the following are true:

1. **Observed RED**
   - At least one meaningful failure has been observed without the real skill guidance.

2. **Observed GREEN**
   - The same scenario shows a meaningful improvement when the draft guidance is applied.

3. **Loopholes captured**
   - Important rationalizations and boundary failures have been recorded in the loophole register.

4. **Loopholes closed**
   - Draft wording or structure has been tightened enough that the same issue no longer reproduces.

5. **Invocation boundary is clear**
   - An agent can tell when to use:
     - baseline
     - android
     - ios
   without mixing them together.

6. **Scope remains honest**
   - The drafts still focus on readiness, debugging, evidence interpretation, and remediation rather than generic UI coding help.

7. **Phase 05 remains independent**
   - Skill publication planning must not be confused with release acceptance or shipped product truth.

## Publication Outcomes

If all gates pass, a later follow-on slice may propose:

- creating real skill files
- running live pressure-test execution sessions
- refining descriptions/frontmatter for actual skill discovery

If any gate fails, keep the work inside `.planning` and continue refinement there.
